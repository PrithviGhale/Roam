# V0.3 manual Gemini / iPhone checklist

Status: not physically executed; live keys were unavailable. Automated tests inject model/provider responses. Work while stationary and record iPhone/iOS/build version, model, backend version and failures, without credentials.

1. Configure Gemini/Maps secrets on the Worker, the phone backend URL/token, and the native iOS SDK key as in README. Check `/health`, then make one text request. A health response alone does not prove key/billing/model authorization.
2. Create a real destination through the existing map UI. Say/type “I’m hungry” and inspect actual Google result cards and attribution. The assistant must not change the route by merely recommending a result.
3. Try “Find me a burger,” “Find Chick-fil-A somewhere ahead,” and “Find something highly rated but not far off route.” Confirm Text Search / route-aware results. Distances/offsets are geometric, with no promised driving detour minutes or verified prices.
4. With numbered results, type “Add the second one.” Confirm the second displayed ID enters the actual stop list, destination remains, and route/ETA/distance update together. Repeat first/third after fresh searches. Names and duplicate names must resolve safely or ask a question.
5. Accept a named recommendation with “Yeah.” Confirm its structured pending ID is used. Say “Don’t add Starbucks,” or provide an ambiguous target; there must be no unapproved change. After ten minutes, old references must require a fresh search.
6. Ask “What’s my ETA?”, “How far away are we?”, “Where are we going?” and “What stops do I have?” Compare responses with current trip state. Original driving time is a calculation snapshot; remaining progress is labeled an estimate. No route means no invented number.
7. “Actually remove that stop” should remove the last successfully added stop. “Remove the coffee stop” should work if unique; multiple plausible stops should prompt a name/number. Removing a specific numbered or named stop should recalculate once.
8. “I need gas” should show verified stations without fuel prices. “I need to pee” should search public bathrooms, without claiming guaranteed access. “Find parking near my destination” should bias to destination, not current GPS.
9. “Cancel my route” should cancel explicitly. An ambiguous “stop for now” should require clarification/acceptance. Confirm cancellation clears line/destination/stops without affecting theme or GPS.
10. Disconnect the backend, use an invalid key/model, deny GPS, trigger quota limits, and simulate provider failure. Existing routes must survive AI failures. A failed conversational stop calculation must retain the previous stop plan/route; never show “added” before successful recalculation. UI route controls must still work independently.
11. Cancel/change destination on the map while AI is thinking. Old tool calls must not change the new trip. Rapid repeated Send/Add taps must not overlap or duplicate mutations. Background/dismiss the assistant during requests and confirm pending work stops.
12. In Expo Go tap the microphone: show a development-build explanation while text/TTS remain functional. In a speech-enabled development build grant microphone and speech permissions; tap, speak, and tap again to finish. Check final transcription sends once. Deny permission / interrupt with Siri or a call / disconnect recognition network and verify fallback.
13. Test twenty-second capture limit, no background recording, and dismissal/background during permission requests or recognition. Native capture must stop even if a transcription error occurs. No persisted audio files or wake word.
14. With Voice replies on, check concise automatic speech after a voice request or during a started trip. Place lists must not be read automatically. Stop/interrupt speech and verify no overlap or late restart; switch tabs and background. Test silent-mode/ringer behavior and audio routing on a physical iPhone.
15. Repeat the existing map/trip checklist in Dark and Light, with keyboard, small screen/large text and long place names. Confirm result card Add Stop controls and Google/third-party attribution stay readable.

Before publishing: configure the prototype token, adjust browser origin allowlist, verify Google key API/native restrictions, set upstream quotas/billing alerts, and add public privacy/terms plus real user auth. Cloudflare rate bindings are per location, not a global billing cap. No public deployment was performed as part of these checks.
